# Демонстрация LeadFlow заказчику

Сценарий на 15 минут, тестовые данные, доступы и честный список того, что показывается по-настоящему, а что имитируется.

## Подготовка (за 5 минут до встречи)

```bash
npm ci
npm run build
npm run demo:reset     # вернуть демо-данные к исходным
npm run demo           # http://localhost:3000
```

Откройте две вкладки: **панель** http://localhost:3000/login и **сайт** http://localhost:3000/. Страница входа сама показывает демо-доступ.

| Почта | Роль | Пароль |
|---|---|---|
| `admin@example.com` | администратор | `leadflow-demo` |
| `olga@example.com`, `denis@example.com`, `marina@example.com` | менеджеры | `leadflow-demo` |

Скриншоты экранов лежат в [docs/screenshots](screenshots) (обновляются командой `npm run screenshots` при запущенной демо).

## Что в демо настоящее, а что нет

| Что показываем | Как это на самом деле |
|---|---|
| Форма на сайте, проверка полей, защита от дублей и спама | **Настоящее**: данные сохраняются в базе |
| Заявки, статусы, ответственные, комментарии, история | **Настоящее** |
| Вход, роли, запрет менять чужие заявки | **Настоящее**: проверяется на сервере |
| Автоназначение по правилам | **Настоящее** |
| Dashboard и периоды | **Настоящее**: считается по базе; 40 заявок в нём **вымышленные** и помечены |
| «Отправлено в Битрикс24», ID лида, ответы портала, ошибки портала | **Имитация.** Портал не вызывается, ID выдуманы. Везде метка «демо» и баннер сверху |
| Повторы при сбоях, очередь, журнал | **Настоящая логика**, но на имитации портала |
| Боевой режим с реальным Битрикс24 | **Не показывается**: не проверялся на живом портале |
| Публичный сайт | Только страница с формой, не полный сайт |

Если заказчик спросит «это уже работает с нашим Битрикс24?»: нет, интеграция написана и проверена тестами на имитации; подключение к вашему порталу займёт настройку вебхука и пробный запуск на тестовом портале.

## Сценарий

**1. Dashboard (администратор), 2 минуты.**
Войдите как `admin@example.com`. Покажите показатели, график по дням, распределение по статусам, популярные услуги. Переключите **Неделя / Месяц / Квартал**, затем задайте произвольный период. Обратите внимание на жёлтую плашку: 40 заявок демонстрационные. Нажмите **«Скрыть демо-данные»**: цифры пересчитаются по реальным заявкам (пока их нет, всё по нулям, и страница это показывает). Верните демо-данные.

**2. Заявка с сайта, 2 минуты.**
На вкладке сайта заполните форму (услуга «Интеграция с Битрикс24»), отправьте. Дождитесь «Заявка принята» (форма не принимает ответ быстрее двух секунд: это защита от ботов). Нажмите «Отправить» дважды: дубля не будет.

**3. Заявка в панели, 3 минуты.**
Откройте **Заявки**: новая заявка сверху. В карточке видно:
- ответственный назначен автоматически (правило «Интеграции: Ольге»), и это записано в истории;
- блок Битрикс24: «Отправлено» с меткой «демо» и пояснением, что это имитация;
- смените статус на «В работе», добавьте комментарий: оба изменения появятся в истории и в списке «Изменения для Битрикс24».

**4. Сбой интеграции, 3 минуты.** *Показывает главное: заявка не теряется.*
Отправьте с сайта заявку на почту вида `клиент@bitrix-error.test`: имитация портала всегда отвечает ошибкой. В карточке: «Ошибка отправки», код `QUERY_LIMIT_EXCEEDED`, время следующей автоматической попытки. Нажмите **«Повторить отправку (демо)»**: попыток станет две. Затем отправьте заявку на `клиент@bitrix-flaky.test`: первая попытка падает, ручной повтор проходит. Добавьте комментарий `проверка [demo-error]`: он сохранится в истории, а его отправка в CRM упадёт и будет ждать повтора.

**5. Журнал синхронизации, 1 минута.**
**История синхронизации**: каждая операция с типом, заявкой, ID в Битрикс24, статусом и числом попыток. Отфильтруйте «Ошибка», откройте запись: видны код, сообщение и режим («Демонстрационный»). В журнале нет паролей и адресов вебхуков.

**6. Роли, 2 минуты.**
Выйдите, войдите как `olga@example.com`. Менеджер видит только Dashboard, Заявки и Клиентов. Откройте заявку другого менеджера (фильтр «Ответственный: Денис Климов»): поля заблокированы с объяснением. Попробуйте открыть `/admin/settings`: «Недостаточно прав».

**7. Автоматизация и ручные заявки, 1 минута (администратор).**
**Автоматизация**: два правила, переключатель «Включено», история срабатываний. **Заявки → Новая заявка**: создание заявки по телефонному звонку.

**8. Интеграция и телефон, 1 минута.**
**Битрикс24**: режим «Демо», таблица соответствия полей, инструкция подключения. Откройте панель на телефоне или в эмуляции устройства (F12): меню, фильтры, карточка заявки.

После встречи: `Ctrl+C` в окне с демо и `npm run demo:reset`.

## Тестовые данные

- **40 вымышленных заявок** за последний месяц (имена и адреса `@example.com`, телефоны `+7900111…`), все с пометкой «демо-запись». Статусы распределены по всем пяти.
- Две заявки с ошибкой отправки для показа повторов: **Наталья Громова** (исчерпаны автоматические попытки, нужен ручной повтор) и **Сергей Ким** (`INSUFFICIENT_SCOPE`: у вебхука нет права CRM).
- Правила: «Интеграции: Ольге, сайты: Денису» и «Остальные по кругу».
- **Служебные адреса имитации портала:**
  - `...@bitrix-error.test`: отправка в CRM всегда падает;
  - `...@bitrix-flaky.test`: первая попытка падает, повтор проходит;
  - комментарий с текстом `[demo-error]`: его отправка в CRM падает (портал «недоступен»).
- Реальных персональных данных в проекте нет. Не вводите настоящие данные в демо-стенд: он сохраняет их в локальную базу.

## Ключевые возможности для презентации

1. **Заявки не теряются.** Сначала сохранение, потом отправка. Портал упал: заявка в системе, повтор автоматический и ручной.
2. **Прозрачность интеграции.** Журнал каждого обращения к Битрикс24 с кодами ошибок и числом попыток.
3. **Нет дублей.** Двойной клик, повтор запроса, потеря ответа портала: лид в CRM один.
4. **Менеджеры работают быстрее.** Автоназначение по услуге или по кругу, карточка с историей и комментариями, поиск и фильтры.
5. **Чёткие права.** Менеджер видит всё, но меняет только своё; настройки и интеграция только у администратора.
6. **Аналитика без выгрузок.** Показатели, конверсия, график, услуги и источники за любой период.
7. **Демо честно называет себя демо.** Имитация отмечена везде, а боевой режим включается одним переключателем после настройки вебхука.
8. **Работает на телефоне.**
9. **Простое развёртывание.** Один процесс Node.js и один файл базы, без внешних сервисов.

## Чего не обещать

- Проверенной работы с вашим Битрикс24, пока она не проверена на тестовом портале.
- Полноценного публичного сайта: сейчас есть только страница с формой.
- Развёртывания на Vercel или с Supabase: проект рассчитан на постоянный сервер с диском.
- Обратной синхронизации из Битрикс24 и уведомлений менеджерам (почта, мессенджеры).
